# 陈的 Markdown 长期记忆

长期记忆由 `group_friend/markdown_memory.py` 实现，主程序和实网测试共用。配置示例：

```json
{
  "memory_enabled": true,
  "memory_path": "state/memory",
  "memory_capacity_mb": 256,
  "memory_retention_days": 180,
  "memory_context_chars": 2000,
  "memory_context_items": 6,
  "memory_recall_context_messages": 6,
  "memory_recall_probability": 0.33,
  "memory_keyword_similarity": 0.8
}
```

`memory_path` 是目录，不再指向 SQLite。旧数据库不会自动读取、转换或删除。当前本地配置已启用 Markdown 记忆，容量已单独设置为 1024 MB；上例的 256 MB 为程序默认值。

## 查看与维护

打开 `state/memory/README.md`，通过链接找到对应用户的笔记：

```text
state/memory/
  README.md                    用户目录索引
  <平台身份的本地指纹>/
    profile.md                 可人工编辑的长期笔记
    events/
      <消息指纹>.md            来信或已确认回复的原文、时间和来源
```

目录使用平台身份指纹隔离，不依赖可能重名或变化的昵称。`profile.md` 可以写稳定偏好、称呼和重要更正，保存后下次生成回复会读取。长期笔记应简洁；默认最多取其前 1000 个字符。它是对话参考资料，不能覆盖 persona 或系统规则。

事件文件使用 Markdown 引用展示原文，文件头注释保存消息标识、方向、时间及来源。不要修改其头部注释；元数据损坏或文件名不匹配时会被忽略。要更正或删除某条记忆，可在停止程序后编辑或删除对应文件；删除记忆不会删除发送回执，也不会要求重新发送。陈不会执行聊天中要求读取、修改本地文件的指令。

## 自动记忆与检索

- 生成阶段保存本次待回复的文字来信。按平台消息及内容指纹去重，重试和重启不会重复建档；不会为首次历史基线自动补建档案。
- 发送阶段只有在网页确认发送成功后，才保存那条实际回复。未发送草稿、取消任务和未知发送不会写成“说过的话”。
- 只处理文字，不声称记住图片或音视频内容。人工发送的回复仍可作为网页上下文，但不会自动标为陈的回复。
- 每次生成前，使用下述关键词匹配与随机门控读取长期记忆；已在当前快照中的事件不重复注入。没有额外模型调用或向量服务。
- 默认最多注入 6 条事件，人工笔记与事件序列化后总长度不超过 2000 字符。较长记录会截断；检索不能保证每次都找到所有相关内容。
- 保留原话和来源，不自动将来信认定为事实，也不将陈在角色扮演中编造的故事写成永久人设。当前明确更正优先于过去的陈述。需要稳定摘要时可人工维护 `profile.md`。

## 关键词匹配与随机召回

模块为 `group_friend/memory_recall.py`，参数位于当前回复配置：

- `memory_recall_context_messages=6`：最近 6 条有效文字消息，包含本次来信和此前双方发言；不使用尚未轮到的后续消息。它与注入模型的网页历史条数、召回事件数量是三个不同参数。
- `memory_keyword_similarity=0.8`：关键词模糊相似度下限。英文忽略大小写并统一全半角，中文提取短词和相邻双字/三字词，过滤常用虚词及历史 `[AI]` 标记。完全相同关键词直接匹配，否则用简单字符串相似度；单个共同汉字不构成匹配，不做语义或同义词推理。
- `memory_recall_probability=0.33`：有匹配后抽取一次 `[0,1)` 随机数，严格小于 0.33 才注入长期记忆，恰为 0.33 时不注入。一次抽样控制该次生成尝试的整个记忆块，不为每条事件各抽一次。

没有关键词匹配就不抽样，也不再用“不相关但最近”的事件兜底。有匹配但抽样未通过时，长期事件和人工笔记都不注入；普通回复仍正常生成。人工笔记正文也可触发匹配，自动生成的 Markdown 标题不算内容；通过门控后仍受总字符预算限制。0.33 是随机概率，模糊匹配下限 0.8 与它不是同一个参数。

这里“久远”指当前网页快照之外、但仍在保留期内的记录，不另设固定天数。记录继续正常保存，门控只改变是否带入本次模型请求。概率可设为 0（不注入）或 1（匹配后必定注入）；不会因此删除记忆。模型失败重试属于新的生成尝试，会重新检索与抽样；已生成且等待发送的回复不会重复生成。

日志事件 `memory_recall` 记录匹配数量、最高分、概率、随机值、是否注入和原因 `included/no_match/random_rejected/budget_exceeded`，不记录聊天正文或关键词。注入后要求陈在相关时自然引用，不强迫每次复述往事。该功能使用本地 Python，不增加额外 DeepSeek 请求。

## 保留、容量与运行

自动事件默认保留 180 天；超期事件不再参与检索，下次写入时清理。自动事件和笔记共用配置中的容量上限；容量不足时先删除最早的自动事件，人工笔记和索引不会被自动删除。文件写入通过进程锁和原子替换完成，避免并发和中断造成半份记录。

`--dry-run` 和 `--mock` 可读取已有记忆，但不会新增、更新或清理记忆文件。`--inspect`、`--status` 不访问长期记忆。单独 `receive` 阶段仍只负责采集入队，记忆写入发生在 `generate` 和确认发送的 `send` 阶段。

记忆读写错误记录为 `memory_unavailable`，不输出聊天正文或异常正文；回复流程会继续，已确认发送不会因为记忆失败而重发。磁盘故障导致未保存的记忆不会自动重建。Markdown 记忆是本地明文，位于 Git 忽略的 `state/` 中；`.env`、Cookie、配置文件不会作为记忆读取。

正常启动：

```bash
uv run run_friend.py --live
```

当前运行中的进程需要重启才能加载新模块和配置。
